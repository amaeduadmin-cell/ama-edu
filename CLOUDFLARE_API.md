# Public API and Cloudflare edge enforcement

AMA EDU's public API is exposed by the `public-api` Supabase Edge Function and is intended to sit behind an API hostname such as `api.amaedu.com.ng`. The function accepts `GET` requests with an `x-ama-api-key` header and never accepts a service-role key or a tenant identifier from the caller. The key itself identifies the school; database queries are filtered by the school resolved from that key.

## Endpoints

| Endpoint | Scope | Response |
| --- | --- | --- |
| `GET /v1/schools/{slug}` | `school:read` | Public school profile fields |
| `GET /v1/schools/{slug}/students?limit=50` | `students:read` | Bounded student directory fields |
| `GET /v1/schools/{slug}/notifications` | `notifications:read` | Bounded notification events |

API keys are generated by an administrator from **API & integrations**. The complete token is displayed only once, stored hashed, scoped, revocable, and limited to 120 requests per minute per key. Cloudflare should add a lower global/IP limit for abuse protection.

## Webhooks and integrations

School administrators can register HTTPS webhook endpoints for `notification.created`. New in-app notifications are queued in `notification_deliveries`. The trusted `notification-dispatcher` function posts a JSON envelope containing `event`, `delivery_id`, and `data`, with `X-AMA-Signature: sha256=...` generated from the `WEBHOOK_SIGNING_SECRET` Edge Function secret. Delivery retries use exponential backoff and stop after six attempts.

## Cloudflare deployment checklist

Create an API hostname or route that proxies only `/v1/*` to the `public-api` function. Configure API Shield JWT validation only if a separate Cloudflare-issued JWT is introduced; the application API-key check remains authoritative. Add WAF rules to block non-GET methods, oversized request bodies, malformed paths, and obvious credential-scanning traffic. Add rate limiting at the edge and preserve `x-ama-api-key` only for the upstream API route. Never log that header.

The API function has `verify_jwt = false` intentionally because external API clients do not have Supabase user JWTs. This does **not** make the endpoint open: the function validates the scoped API key, verifies its hash through a service-role-only database RPC, applies the database-backed per-key window, and constrains every query to the key's school.

The trusted `notification-dispatcher` route must not be public. Configure it as a scheduled/internal request with `AMA_AUTOMATION_SECRET` and `WEBHOOK_SIGNING_SECRET` set as Supabase Edge Function secrets. Keep the existing payment webhook separate because payment-provider signatures and event semantics differ from AMA EDU notification webhooks.

The current repository contains the application-side controls and deployment contract. Cloudflare DNS, WAF, API Shield, rate-limit rules, and secrets remain environment-specific operations and require the production Cloudflare account to be configured.
